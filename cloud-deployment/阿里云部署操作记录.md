## 3. 增加 2 GiB Swap

服务器只有约 1.6 GiB 可用物理内存。Docker 构建 Python 镜像或 MySQL 短时占用上升时，可能触发系统 OOM，导致进程被杀死。因此增加 2 GiB Swap 作为内存缓冲：

```bash
fallocate -l 2G /swapfile
chmod 600 /swapfile
mkswap /swapfile
swapon /swapfile
printf '/swapfile none swap sw 0 0\n' >> /etc/fstab
printf 'vm.swappiness=10\n' > /etc/sysctl.d/99-aimemories.conf
sysctl --system
free -h
```

各命令作用：

- `fallocate` 创建 2 GiB 的 Swap 文件。
- `chmod 600` 只允许 root 读写，防止其他用户读取内存换出内容。
- `mkswap` 将文件格式化为 Swap。
- `swapon` 立即启用 Swap。
- 写入 `/etc/fstab`，保证重启后仍自动启用。
- `vm.swappiness=10` 让系统优先使用物理内存，仅在内存紧张时使用 Swap。

验证结果应包含：

```text
Swap: 2.0Gi
```

如果 `sysctl --system` 最后仍显示 `vm.swappiness = 0`，说明其他系统配置文件在后面覆盖了它，需要找出重复设置并保证最终值为 10：

```bash
grep -R '^vm.swappiness' /etc/sysctl.conf /etc/sysctl.d
sysctl vm.swappiness
```

## 7. 生成数据库随机密码

为 MySQL 普通用户和 root 用户分别生成不同的 48 位十六进制随机密码，并写入 `.env.production`：

```bash
cd /opt/ai-memories/backend && \
ai_db_pw=$(openssl rand -hex 24) && \
ai_root_pw=$(openssl rand -hex 24) && \
sed -i "s/^MYSQL_PASSWORD=.*/MYSQL_PASSWORD=$ai_db_pw/" .env.production && \
sed -i "s/^MYSQL_ROOT_PASSWORD=.*/MYSQL_ROOT_PASSWORD=$ai_root_pw/" .env.production && \
unset ai_db_pw ai_root_pw && \
echo "数据库密码已安全更新"
```

这样做的原因：

- 应用连接数据库使用 `MYSQL_PASSWORD`。
- 数据库管理账号使用另一份 `MYSQL_ROOT_PASSWORD`。
- 随机密码不会出现在终端输出中。
- 两个账号使用不同密码，减少一个密码泄露后的影响。

真实密码不应截图、发到聊天中或写进 Git。

## 10. 清理 macOS AppleDouble 文件

首次启动 API 时出现：

```text
SyntaxError: source code string cannot contain null bytes
```

检查发现压缩包中带有 macOS 自动生成的 `._*.py` 元数据文件。它们不是 Python 源码，但 Docker 构建时被复制进了镜像。

定位文件：

```bash
python3 -c 'from pathlib import Path; bad=[str(p) for p in Path("alembic").rglob("*.py") if b"\x00" in p.read_bytes()]; print(bad if bad else "没有发现含空字节的 Python 文件")'
```

清理所有 AppleDouble 文件：

```bash
find /opt/ai-memories/backend -type f -name '._*' -delete
echo "macOS 元数据已清理"
```

本地 `.dockerignore` 也加入了：

```text
._*
```

这样以后重新打包时，这类文件不会再次进入 Docker 镜像。

## 15. 允许新的访问主机名

把公网 IP 和 `nip.io` 地址加入 FastAPI 的 Host 检查名单：

```bash
cd /opt/ai-memories/backend && \
sed -i 's/^ALLOWED_HOSTS=.*/ALLOWED_HOSTS=localhost,127.0.0.1,47.82.83.74,aimemory.47-82-83-74.nip.io/' .env.production && \
grep '^ALLOWED_HOSTS=' .env.production
```

`ALLOWED_HOSTS` 的含义是允许请求携带这些 `Host` 值。它不会配置 DNS、开放端口或提供登录权限。

请求：

```text
https://aimemory.47-82-83-74.nip.io/health
```

会携带：

```text
Host: aimemory.47-82-83-74.nip.io
```

如果不在名单中，FastAPI 会返回 `400 Invalid host header`。

## 16. 创建单家庭登录账号

为了避免任何人发现公网地址后直接访问家庭数据或消耗百炼额度，使用 Nginx Basic Authentication 提供单家庭账号保护。

安装密码工具：

```bash
apt-get update && apt-get install -y apache2-utils
```

创建用户名为 `family` 的账号：

```bash
htpasswd -cB /etc/nginx/.htpasswd family
```

终端会隐藏密码输入，并要求输入两遍。参数含义：

- `-c`：创建新的密码文件，仅第一次创建时使用。
- `-B`：使用 bcrypt 哈希保存密码。
- `/etc/nginx/.htpasswd`：Nginx 读取的密码哈希文件。

这里的家庭密码不是 MySQL 密码，也不是服务器 SSH 密码。

## 17. 配置 Nginx 反向代理和登录保护

创建 `/etc/nginx/sites-available/aimemory`：

```nginx
server {
    listen 80;
    listen [::]:80;
    server_name aimemory.47-82-83-74.nip.io;

    client_max_body_size 50M;

    location ^~ /.well-known/acme-challenge/ {
        root /var/www/html;
        auth_basic off;
    }

    location / {
        auth_basic "AI Memories Family";
        auth_basic_user_file /etc/nginx/.htpasswd;

        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 180s;
    }
}
```

启用站点并重新加载 Nginx：

```bash
ln -sfn /etc/nginx/sites-available/aimemory /etc/nginx/sites-enabled/aimemory
rm -f /etc/nginx/sites-enabled/default
nginx -t && systemctl reload nginx
```

配置项作用：

- `client_max_body_size 50M`：允许上传图片，同时限制异常超大请求。
- `/.well-known/acme-challenge/`：允许证书机构验证域名，不要求家庭密码。
- `auth_basic`：其余请求必须提供家庭账号密码。
- `proxy_pass`：把验证通过的请求交给本机 FastAPI。
- `X-Forwarded-*`：把原始 IP 和协议告诉后端。
- `proxy_read_timeout 180s`：为 AI 生成等较慢请求预留时间。

## 19. 让 FastAPI 正确识别 HTTPS 代理

首次连接 iOS 时，FastAPI 对缺少末尾 `/` 的路径产生重定向。因为 Uvicorn 没有信任 Docker 外部 Nginx 的代理头，重定向地址错误地使用了 `http://`，随后被 iOS App Transport Security 拦截。

Dockerfile 的启动命令增加：

```text
--proxy-headers --forwarded-allow-ips=*
```

服务器修改命令：

```bash
cd /opt/ai-memories/backend && \
sed -i 's/--timeout-keep-alive 10/--timeout-keep-alive 10 --proxy-headers --forwarded-allow-ips=*/' Dockerfile && \
tail -n 1 Dockerfile
```

因为 FastAPI 的 `8000` 端口只绑定 `127.0.0.1`，只有本机 Nginx 能访问，所以在这里信任代理头是可接受的。

重新构建并重启 API：

```bash
docker compose --env-file .env.production -f docker-compose.demo.yml build api
docker compose --env-file .env.production -f docker-compose.demo.yml up -d --force-recreate api
```

数据库和照片位于命名卷中，重建 API 容器不会删除它们。

## 21. 当前安全边界

当前演示环境具有以下保护：

- 所有公网 API 请求使用受信任的 HTTPS 证书。
- HTTP 自动跳转到 HTTPS。
- Nginx 在请求进入 FastAPI 前要求家庭账号密码。
- 家庭密码仅以 bcrypt 哈希形式保存在服务器。
- iPhone 真机使用系统钥匙串保存登录信息。
- `.env.production` 权限为 `600`。
- MySQL 没有公网端口。
- FastAPI 的 `8000` 端口仅监听 `127.0.0.1`。
- 数据库密码和百炼 API Key 不写入客户端。

当前认证适合单家庭演示。若以后增加多个家庭、邀请成员、找回密码或权限角色，应改为 FastAPI 登录接口、短期访问令牌和刷新令牌体系。

## 22. 阿里云防火墙建议

只允许必要端口：

| 端口 | 用途 | 是否公网开放 |
| --- | --- | --- |
| 22 | SSH / Workbench 运维 | 是，最好限制来源 IP |
| 80 | Certbot 验证和跳转 HTTPS | 是 |
| 443 | App 的 HTTPS API | 是 |
| 8000 | FastAPI | 否 |
| 3306 | MySQL | 否 |

不要在阿里云防火墙中开放 `8000` 或 `3306`。

4. 定期检查磁盘、Swap 和容器日志。
5. 正式发布前购买自有域名，替换 `nip.io` 地址。
6. 多家庭版本改用后端令牌认证和数据库级家庭权限校验。

## 27. 故障排查顺序

App 无法连接时，按下面顺序检查：

```bash
# 1. Docker 是否运行
systemctl is-active docker

# 2. 两个容器是否正常
cd /opt/ai-memories/backend
docker compose --env-file .env.production -f docker-compose.demo.yml ps

# 3. FastAPI 本机接口是否正常
curl -sS http://127.0.0.1:8000/health

# 4. Nginx 是否正常
nginx -t
systemctl is-active nginx

# 5. 公网 HTTPS 和登录是否正常
curl -u family https://aimemory.47-82-83-74.nip.io/health

# 6. 查看 API 日志
docker compose --env-file .env.production -f docker-compose.demo.yml logs --tail=100 api
```

判断方式：

- 第 3 步失败：检查 API 或数据库容器。
- 第 3 步成功、第 5 步失败：检查 Nginx、证书、密码或阿里云防火墙。
- 两步都成功但 App 失败：检查 iOS API 地址、登录信息和客户端日志。
