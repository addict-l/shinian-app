# 拾年第一阶段开发清单

状态：2026-10-10 用户授权依次完成第 1–3 次提交，每个任务对应验证通过后单独提交并推送。每一步验证可运行的行为，不以文件已创建作为功能完成依据。

## 提交与验证规则

1. 需求文档、术语与验收标准：检查 Markdown 本地链接，验证文档检查器。
2. T01 数据与接口基础及测试目录迁移：验证兼容迁移、结构化信息校验、接口往返与 App 构建。
3. T02 多图消息：验证文本加多图、纯图不调用 AI、限制、失败重试及消息关联；运行前端状态与网络测试。
4. 后续提交依次对应 T03–T07，本轮不提前实施。

每个节点通过后生成独立提交并推送 `origin`，记录主工程提交号和同级验证目录版本。测试源码保留独立本地 Git 记录；构建产物不提交。推送不等于云端部署或全流程验收完成。

## T01 数据与接口基础

已实现并于 2026-10-10 验证：后端 30 项测试、前端 18 项单元测试和网络检查通过；真实本机 MySQL 旧数据升级、回退、再次升级通过；不含验证目录的独立前端副本构建通过。尚未部署云端。验证源码独立保存于同级目录。

先将现有测试源码与验证脚本迁移至同级 `shinian-validation`，调整测试入口；开发日志、截图、构建缓存与测试结果输出至该目录的 `artifacts/`。主工程独立构建运行不得依赖验证目录或本机绝对路径。测试源码独立保留版本，记录对应主工程提交号，临时产物不提交。

增加信息维度状态、可读描述、消息图片关联、版本字段及兼容迁移，更新前后端数据类型和接口契约。

验证：测试迁移后仍能运行，缺少验证目录时主工程仍可构建 App；旧数据迁移不丢失；模糊、未知与未采集可区分；图片正确关联消息；记录对象与出场人物不混淆。

## T02 讲述消息与多图

实现多图选择、压缩、上传状态、纯图片消息、固定提示、认证加载与稳定请求标识。

验证：文字加照片、纯照片、上传限制、部分失败和重试；纯图路径不调用 AI。

## T03 引导与就绪

实现已有信息提取、单问题引导、缺项与矛盾处理、就绪建议和有原文依据的第一人称草稿生成。使用假模型测试业务规则，再安排少量真实模型验收。

验证：模糊时间等有文字表达；不把尚未问到的信息当未知；不分析图片或补造事实；不按固定轮数放行。

## T04 暂停恢复与本机待发送内容

增加未完成故事列表、跨设备读取恢复、当前设备输入持久化以及手动重试。完善录音开始、停止、转写修改与识别错误提示。

验证：App 重启、断网、超时、再登录同账号恢复；重复请求不会重复创建内容。

## T05 草稿与回忆维护

实现标题正文直接编辑、重新生成确认、保存编辑版本、已保存信息更新、多设备版本冲突处理和整段故事删除。关联数据库删除与图片清理需可恢复重试。

验证：校对结果实际持久化；重新生成不静默覆盖；删除取消和确认结果正确。

## T06 人物回忆录与 PDF

按记录对象加载全部已保存回忆，支持默认时间排序、手动顺序、照片选择顺序、回忆录名称、封面、目录、分页、预览和分享。

验证：不混入其他人物的第一人称故事；长文及多图可正常分页；内容与目录完整；导出使用本次快照。

## T07 集成与交付

运行必要的后端集成测试、前端构建和行为测试，更新 README 的环境与启动说明。准备兼容云端部署步骤、数据库及照片备份步骤和回退方案，核对后再执行部署。

验证：老师在另一台 Mac 启动模拟器；家庭真机完成语音到 PDF 的全流程。记录通过、失败和需用户实际操作的项目，不将未执行的真机验收标为通过。
