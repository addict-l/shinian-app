## 提交与验证规则

1. 需求文档、术语与验收标准：检查 Markdown 本地链接，验证文档检查器。
2. T01 数据与接口基础及测试目录迁移：验证兼容迁移、结构化信息校验、接口往返与 App 构建。
3. T02 多图消息：验证文本加多图、纯图不调用 AI、限制、失败重试及消息关联；运行前端状态与网络测试。
4. 后续提交依次对应 T03–T07，本轮不提前实施。

每个节点必须按“编写代码与本机验证 → 同步到云服务器 → 云端运行及对应接口验证 → 用户人工审查 → 云端本地 Git 提交 → Mac Git 提交并推送 `origin`”完成，记录主工程提交号、实际部署版本与同级验证目录版本。云端未通过或暂时无法访问时，不提交或推送该任务。测试源码保留独立本地 Git 记录；构建产物不提交。

## T03 自然对话、信息分析协作与草稿生成

状态：已完成。2026-10-11 用户完成实际流程人工审查，认可 T03 并授权以“完成ai对话引导 就绪判断和信息提取”提交。本机与云端各 139 项后端测试、原受影响会话 3 次只读真实模型重放通过；客户端沿用前次 36 项 Swift、4 项自然对话 UI 与独立 Release 验证记录，照片界面和 7 组、22 轮合成场景记录保留。最后一轮后端修正未重跑客户端测试。长篇回忆草稿的整理质量列为后续改进，不在本次修改。详见 [验证记录](validation-record.md)。

目标：用户感受到的是有人认真听故事、顺着内容交流并适度引导。完整度分析在后台辅助对话，不能把用户聊天变成按字段逐项问答。

2026-10-10 用户已逐项确认七项交互规则，详见 [需求记录](phase-1-requirements.md)。本阶段按这些规则实施，旧版测试通过不代表修订版已完成。

实施范围：

- 信息分析模型读取用户原文、已有信息和相关对话上下文，提取有原文依据的信息，区分缺失、明确、模糊、记不清与拒绝，识别影响理解的矛盾；后端校验依据并计算就绪。
- 对话模型读取记录对象、已有对话、用户最新表达，以及本轮经过校验的信息状态、就绪结果和引导建议，自行组织用户可见的自然回复。两种职责复用现有百炼接入，由后端按同一会话和消息版本串联，不要求部署两个不同模型。
- 对话始终面向被记录的父母，子女负责转述和输入；语气像温和、有好奇心的晚辈。通常两三句话、按内容调整，先承接具体讲述再按需追问；需要追问时最多一个问题，也允许只回应。根据故事内容决定重点，不按固定字段顺序盘问，不输出内部完整度清单；事实分析继续区分讲述者与记录对象。
- 用户已说过、明确记不清或拒绝的信息不能反复询问。用户更正、情绪表达、简短回答、主动结束或要求生成时，回复须结合当前语境处理；不得虚构事实、感受或声称看过照片。
- 聊天页的生成提示同样使用面向用户的自然说明，不展示要求逐项补齐的信息清单；后台信息状态继续保留，供协作与事实校验使用。
- 同一段回忆只在合适停顿自动建议生成一次，模型语言提示与按钮同轮出现。下一条讲述发出后按钮收起；此后只有用户明确请求整理或保存，才再次提示并显示按钮。信息就绪与显示按钮分别管理，不设置常驻生成入口，不因消息重试或重新加载重复自动提示。
- 讲到另一件事时先顺着听，在自然停顿询问是否另记一篇，由父母决定；不自动拆分或保存。情绪回应以实际表达为依据，温和承接，尊重拒绝，不放大情绪或急着劝慰。
- 时间、地点和感受继续记录与适度引导。主要人物、具体事件和基本经过足以理解且无关键矛盾时，可以建议生成；用户也可主动结束并生成。辅助信息缺失不要求用户逐项回答或拒绝。缺失保持 missing，不改成 unknown，也不在草稿中编造补齐。
- 点击生成时由草稿模型基于经过校验的讲述依据生成记录对象第一人称草稿，保留更正、拒绝与事实校验约束。
- 用户口头提出“保存”也先显示生成入口、进入草稿预览与校对，确认后才保存；模型不得自行保存回忆。未达到基础生成条件时自然说明并适度引导，不能通过按钮提示绕过事实与就绪校验。
- 两次模型调用都须对应同一版讲述；任一失败保留用户消息并支持重试，不输出固定问卷问题冒充模型回复，不重复保存消息，也不沿用旧的就绪结果。纯图片消息继续使用 T02 固定保存提示且不调用模型。

- 用户文字以靠右、有背景和边界的气泡显示，发送后立即回显并清空输入框，AI 回复随后追加。上传与等待过程显示进度，重试不重复显示消息；照片加文字保持同组，纯照片不出现空文字气泡。
- 进入聊天页面立即显示“开始讲述”欢迎提示，服务端返回后替换为模型开场白，无需先发送消息；加载时可先输入，开场请求失败可以直接重试。模型自然承接用户的保存意图，不把确认需求或暂缓生成的说明误当成生成邀请。

验收：自动化检查验证分析结果确实传给对话模型、上下文与版本一致、重试安全及事实约束，并验证“就绪但暂不提醒 → 首次提示与按钮同轮出现 → 下一条讲述收起 → 后续不再自动弹出 → 明确请求后再次显示”的完整链路；重试与重新加载不重复自动提示，口头保存不跳过草稿确认。真实模型多轮验证覆盖父母亲述与子女代述的统一称呼、长篇讲述、短回答、情绪表达、模糊信息、未知、拒绝、更正、矛盾、话题延伸和主动结束。用户审查回复是否贴合具体讲述、自然且有引导性，无机械轮询、重复问题、强加情绪或催促补齐字段。重新完成本机、云端验证及用户审查后再提交。

## T04 成员聊天恢复与本机待发送内容

状态：2026-10-11 用户试用后取消未完成故事列表，经过八项逐条确认，授权按修订边界重做。当前实现每位成员唯一聊天窗口、最近 20 条记录、保存分界及本机恢复，技术验证和部署记录见 [验证记录](validation-record.md) 与 [部署记录](cloud-deployment-record.md)。2026-10-11 用户完成修订版人工审查，明确授权“T04可以commit了”。T04 标记完成，按云端 → 验证目录 → 主工程提交并推送的链路归档；T05–T07 尚未实施。

点击“新的回忆”先选择家人，再直接进入该成员聊天。显示最近 20 条消息，用户与 AI 分别计数，文字和同次照片算一条。完整历史保留，20 条不限制当前回忆的分析或生成依据。确认保存后留在同一窗口，继续下一篇回忆；已保存故事不混入新草稿。每位家人同时只有一篇待整理回忆，不自动拆分或保存。详见 [需求修订](phase-1-requirements.md#2026-10-11-t04-边界修订)。

同账号已发送聊天可跨设备读取；未发送文字、压缩照片、部分上传结果与待重试标识按服务器、账号和家人隔离保留在当前设备。退出、切换家人、重启或断网后恢复，不自动发送，手动重试沿用原标识。确认保存后清理对应待发送状态，并保留最近聊天缓存；未保存内容不算正式回忆。

录音区分准备、录音与结束转写；停止后等待最终结果，保留原输入供修改。离开页面取消识别，忽略迟到回调；权限或识别错误保留已有文字，不保存原始音频。真机中文语音仍待人工体验。

验证：成员重复进入及跨客户端恢复、并发打开不新建重复内容、最近 20 条与完整依据分离、保存后独立生成两篇回忆、旧故事仅用于对话承接、账号及人物输入隔离、离线恢复与手动重试。客户端界面后续只在用户指定的原 iPhone 17 Pro 模拟器执行，不切换其他模拟器。
