### 会话与说话策略
- 一次会话 = 一位人物按冻结题序连续访谈 4 题（`plan.py`：默认题序中测试集对应材料最多的连续 4 题）。每题：入口问 → 老人答 → v3j 判定（同题 previous_fields / ask_counts / focus 与生产一致）→ 回复 → … ；切题清空本题状态；每题最多 6 次老人回答。
- baseline（改前）= 生产后端 `contract_guided_interview.turn` 的固定话术：追问 = 合同固定问句；本题完成 = “这段可以先整理成草稿了。您还有什么想补充的吗？”；跳过 = SKIP_ACK + 下一题；暂停 = 固定句。
  补充邀请后，老人若只说“没有了/就这些”之类的短句，视为点了“整理草稿”按钮（App 上有该按钮），回复“好，先核对这段草稿，您确认后再保存。”后进入下一题；老人若继续讲，则照生产再判定一次，最多 2 次补充邀请。
- v4（改后）= 说话层（`speaker-prompt.txt`，deepseek-v4-pro，思考禁用）+ 结束规则（`speaker-config.json`）。详见各轮记录。

## 1. 改为 Haiku 文件队列（2026-10-22，接手后）

- 本环境没有 Anthropic API key，Haiku 以 Claude 子代理形式运行，经文件队列服务：
  - 运行器把每个模拟老人请求写成 `<runs>/persona-queue/<id>.request.json`（自包含：完整 system 指令 + user 内容 + 输出格式），阻塞等待同名 `.response.json`；打分用 `<runs>/scorer-queue/`。
  - `tools/interview_eval/simulate/queue_worker.py`：`next <persona|scorer|all> [wait秒]` 在队列锁（flock）下领取一个未答请求并打印完整内容，没有则等待后打印 IDLE；领取超过 TTL（persona 300s / scorer 600s）未答的可被重新领取；
    `answer <队列> <id>` 从 stdin 读 JSON、按请求内的校验规则检查（persona：只有非空 reply；scorer：每个待打分编号 5 维 1–5 整数 + 合法违规名）后写 response，先交者有效，成功后自动领取下一个；`status` 看队列。
  - `tools/interview_eval/simulate/WORKER.md`：worker 循环 next → 只按请求内指令输出 JSON → answer；不得读其他文件或金标准；扮演老人不得编造资料外事实；严格照“本轮表现”。
- 模拟器不变：只看该人物真实资料、本题对话、系统最后一句；看不到金标准和内部状态；行为（正常/短答/跑题/不想多说/想歇会儿/语音错字）仍由代码按 sha256(人物|题号|第几次回答) 固定抽样并写进请求，Haiku 只按指定行为说话，各版本遇到同一位老人。
- Haiku 回答按请求内容哈希缓存在 `<eval-home>/cache-haiku/<队列>/`（与 DS 缓存分开），改前/改后版本共享每题老人的首次回答（首次回答只看入口问题），因而首次判定也共享 DS 缓存。
- 量表文本（`scorer-prompt.txt`）不变，只是打分模型换成 Haiku；模拟器提示（`simulator-prompt.txt`）不变。
- 运行器改为事件驱动（`run_sim.py` 重写）：每个会话独立推进；老人请求一产生就写入 persona 队列；各会话的 DS 调用汇成一个中转作业（所有存活会话都在等 DS，或最早一个等满 12 秒时发出；同一时间只有一个作业在途）；会话结束立即把各题送 scorer 队列；DS 作业 900 秒（15 分钟）无结果即停止运行并报告。`--rescore RUN` 可只重打分。
