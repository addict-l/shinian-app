## 交付目标

子女协助父母讲述真实故事，通过语音转文字或文字输入与 AI 对话，附上多张照片。故事可以暂停后继续，AI 顺着讲述自然交流并适度引导，后台分析故事信息与就绪，生成父母第一人称的回忆草稿，用户校对后保存。回忆保存后可以修改或整体删除。至少一段已保存回忆即可按人物整理全部故事，调整顺序和照片，预览并导出 PDF。

需求依据为 [需求访谈记录](phase-1-requirements.md)。

## 功能与状态

### 新回忆

选择记录对象；提供自由讲述与可选话题。话题不是强制章节。每次录音手动开始、停止，识别文字可修改后发送。每条消息可包含文字、最多 9 张照片，或两者都有；两者都没有时不能发送。

照片上传前压缩，单张不超过 8 MB，相册原图保持原样。附件与消息、故事关联。纯图片消息保存成功后展示固定提示，不调用 AI，不通过图片补齐故事信息。

### 自然对话、信息分析与就绪

2026-10-10 用户修订 T03，并在逐项访谈后确认七项交互规则：用户可见的回复必须由大语言模型组织，综合后台完整度信息与用户语言、上下文，自然交流并具有引导性。正式规则见 [需求记录](phase-1-requirements.md)。

采用信息分析模型与对话模型两个职责，由后端传递信息协作，复用现有百炼接口和模型配置，无需单独部署两个模型。草稿生成在用户点击生成时独立调用。

每轮文字讲述的链路：保存用户消息 → 信息分析模型提取信息 → 后端校验原文依据并计算就绪 → 对话模型综合本轮分析结果和对话上下文生成回复 → 保存本轮信息与回复 → 返回 App。分析结果不能替代用户原文与完整对话语境；用户看到的是模型组织的回复。

- 信息分析保存人物、具体事件及基本经过、时间、地点、感受、细节的内容、状态与原文依据，并提供有依据的引导建议。后端校验事实依据，独立计算就绪，不直接信任模型给出的布尔值。
- 对话模型接收记录对象、已有用户和助手对话、用户最新表达、本轮经过校验的信息状态、关键矛盾、就绪结果及引导建议。后端保证输入来自同一版讲述，不能拼接旧分析与新消息。
- 对话模型始终面向记录对象交流，以“您”称呼父母，子女代述时也保持这一交流对象；事实分析仍区分人物视角。语气像温和、有好奇心的晚辈，用日常语言回应具体内容。
- 对话通常两三句话，根据内容调整；顺着具体故事和表达，理解父母想继续还是想结束，再选择是否追问以及重点。需要追问时最多一个问题，也允许只回应、邀请继续或建议生成。措辞示例不作为固定回复模板。
- 父母联想到另一段故事时先顺着听，在自然停顿询问是否另记一篇，由父母决定，不自动拆分或保存。
- 缺项用于适度引导，不按固定字段顺序盘问、输出完整度清单或套用固定承接语。温和承接父母实际表达的情绪；平静讲述时不主动放大情绪，不认定未经表达的心理，不急着劝慰，尊重不愿展开的内容。
- 不重复询问已知、明确未知或拒绝的信息。用户更正时更新理解；出现影响理解的矛盾时自然确认，不自行挑选事实，不把新增细节或先后发生的不同事情视作矛盾。
- 就绪以记录对象及主要人物、具体事件和基本经过足以理解且无关键矛盾为基础，不按固定轮数放行。时间、地点和感受继续引导与记录，允许模糊表达，但不作为必须逐项回答或明确拒绝的生成门槛。达到基础条件后可建议生成，用户也可主动结束讲述。
- missing、unknown、withheld 保持不同状态。缺失内容不自动记为记不清；拒绝内容不改写为记不清。草稿忠于现有依据，不编造缺失的时间、地点或感受，也不把后台状态标签写进正文。
- 图片数据不进入模型输入；不能声称看过照片。纯图片消息沿用固定保存提示且不调用模型，该提示不作为讲述事实提取。
- 分析或回复模型失败时保留已发送内容，明确提供重试；不回退为固定问卷回复冒充正常对话。使用稳定请求标识，防止两次调用失败重试产生重复消息或错配信息。仅成功完成本轮分析与回复后发布对应状态，失败时不沿用旧就绪。

#### 生成提示与按钮

信息就绪表示已有事实足以整理；是否在当前轮建议生成，由对话模型结合上下文和提醒状态决定，再经后端检查。不能把 ready 直接映射为始终显示按钮。

| 时机 | AI 与界面行为 |
| --- | --- |
| 故事尚未达到基础生成条件 | 自然回应并适度引导，生成按钮不出现 |
| 已就绪，父母正在投入地继续讲 | 顺着交流，不打断或立即弹出按钮 |
| 同一段回忆首次在合适停顿建议生成 | AI 发出自然语言提示，生成按钮同轮出现；记下本段已自动提示 |
| 按钮出现后，父母发送下一条讲述 | 按钮自动收起，继续交流 |
| 此后继续补充或再次达到就绪 | 不再自动建议生成或弹出按钮 |
| 用户明确请求整理／保存这段回忆 | 满足基础条件时再次发出对应语言提示并显示按钮；不满足时自然说明并引导 |
| 用户点击生成 | 进入草稿流程，预览、修改并确认后才保存 |

后端须区分信息就绪、自动提示是否已发生、当前轮是否显示生成操作以及用户明确请求。提醒状态按同一段回忆管理；请求重试、响应重放与重新加载不得重复触发自动提醒，用户主动请求后的再次显示不算新的自动提醒。模型的语言提示与按钮事件必须一致，不能嘴上建议生成却没有入口，也不能无对应说明地弹出按钮。

建议采用的信息状态：

| 状态 | 含义 | 表达示例 |
| --- | --- | --- |
| missing | 尚未提供 | 按语境适度引导，不能自动标记未知 |
| known | 已明确说明 | “1982 年，在苏州” |
| approximate | 模糊但有信息 | “大概刚参加工作时，在老家附近” |
| unknown | 用户明确记不清 | “具体时间已记不清” |
| withheld | 用户明确不想提供 | “这部分暂不愿讲述” |

每项保存状态、可读文字和原始消息依据。精确日期仅在有依据时用于计算；未知或模糊时间仍有可读表达，不用虚构日期代替，也不向用户只返回 null。

### 暂停、恢复与失败

成功发送的消息保存在服务器。选择家人后直接进入该成员唯一聊天窗口，不展示会话列表或新建会话按钮。页面展示最近 20 条，完整历史保留；当前回忆超过 20 条仍完整分析、整理和关联照片。保存后保留历史并在同一窗口继续下一篇回忆。

成员 ID 是用户可见聊天的稳定身份，既有数据库会话作为内部回忆分段保留，用于隔离事实依据、草稿确认和照片归属。重复进入、跨设备打开由服务器选择并复用当前分段；确认保存后建立下一分段，不重新发开场。旧版遗留历史按成员合并显示最近 20 条，不删除原记录或把不同未保存分段合并成草稿。对话模型获得最近的较早聊天及明确分界以自然承接；信息分析、就绪和草稿只使用当前分段的完整依据。

本机缓存按服务器、账号及家人隔离，使用受保护文件和原子写入，保存文字、照片副本、服务器快照及重试标识，不包含密码或原始音频。部分上传保留结果，用户手动重试只上传未完成照片。重新进入先展示本机缓存，再读取云端最新状态；未发送内容只留原设备。其他设备已保存当前回忆时，将本机未发送内容保留到下一篇，仍由用户手动发送。

建议为消息、上传和草稿确认使用稳定请求标识。超时重试返回同一结果，避免重复消息、照片与已保存回忆。多张图片部分上传失败时保留上传状态；未完成保存前不展示“照片已保存”。AI 失败时保留已发送内容并提供重试，不伪造回复。

### 草稿与已保存回忆

草稿默认采用记录对象第一人称。可以直接编辑标题与正文，或返回对话补充后重新生成。重新生成不能静默覆盖手动编辑，确认保存必须提交用户当前修改的内容。

已保存回忆可以修改标题、正文、时间、地点、感受和照片。不同设备同时编辑时建议使用版本校验：发现旧版本保存则提示重新加载，并保留本机修改供核对，不静默覆盖其他设备内容。

删除前明确说明会删除故事及对应对话、草稿和照片。建议先在数据库事务中删除关联内容，再按可重试方式清理物理图片，避免一部分删掉、一部分残留。App 外已导出 PDF 不受影响。

### 回忆录与 PDF

按记录对象收录全部已保存故事。不能因为妈妈仅出现在爸爸的故事里，就把爸爸第一人称的故事放进妈妈的回忆录。

默认按有依据的发生时间排序；保留模糊时间描述，不能确定先后的放在最后，允许手动调整。日期不明确时不使用创建日期冒充故事发生时间。

默认选中每篇故事的全部照片，允许取消选择与调整顺序；照片放在所属正文之后。整本保留已确认的正文，不再次调用 AI 重写。封面和目录自动生成，名称可修改。

2026-10-11 T06 访谈取代原 A4 建议：使用 A5 竖版（148 × 210 mm），三种封面模板，正文默认 16 pt、可选 14 pt，每篇故事另起页；标题、时间地点及正文合计不超过内容区半页且文字只有一页时，首张照片放在正文下方同页，其余和长文照片在正文后的独立页面完整展示。根据最终排版生成可跳转目录及连续正文页码，处理长故事、长标题、竖横照片与分页。图片失败须重试或由用户明确取消，不能静默漏图。详细业务规则及验收见 [T06 需求](t06/t06-requirements.md)。

从人物详情进入封面、内容、整本预览三步制作，设置自动保存并跨设备同步，离线待同步与多设备整份设置冲突须显式处理。生成 PDF 后预览固定快照，点击分享时联网核对故事和设置；变化须重新生成预览并查看后再分享，核对失败保留预览供重试。后来修改故事只影响新导出的文件，已经分享或存到 App 外的文件保持原有内容。

### T03 原文依据的内部传递

信息分析模型选择同一条用户消息中后端提供的首尾原文片段编号，后端取出中间连续原文，避免模型抄写漏字、改人称或用摘要冒充引文。不存在的消息或片段编号、反向范围会拒绝，并最多请求一次结构修复。草稿模型选择经过过滤的证据索引，后端附回实际用户引文；现有接口与保存记录继续使用原文和消息标识。新旧年份更正、拒绝展开的内容在草稿输入前过滤。
