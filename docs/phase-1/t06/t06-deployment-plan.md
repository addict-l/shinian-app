# T06 部署与回退方案

状态：已按本方案实施，2026-10-11；结果见 [验证记录](../records/validation-record.md) 与 [部署记录](../records/cloud-deployment-record.md)。2026-10-12 用户人工审查通过并授权完成与上传；按本方案的云端 → 验证目录 → 主工程顺序归档。最终版本映射见部署记录。

## 变更与兼容性

- 新增迁移 `f10100000001`，在 T05 `e10100000001` 之后增加人物回忆录设置表和独立封面照片归属字段；不改写既有故事或聊天。
- 新增人物回忆录快照 GET、版本化设置 PUT、独立封面照片 POST。GET 不创建制作设置、不调用模型。
- 新增字段可空，旧 App 与旧后端继续使用既有接口；PDF 本地生成，不增加服务器 PDF 渲染依赖。
- 回忆录设置以人物为唯一主键，家庭与人物归属须核对。设置修改使用版本和请求标识，冲突不覆盖，重复提交不产生第二次修改。

## 顺序

1. 本机独立随机 MySQL 测试库运行迁移和必要后端测试；原 iPhone 17 Pro 上运行客户端状态及界面验证，并检查实际 PDF 渲染。
2. 将不含环境密钥、业务资料及构建缓存的后端源码和独立测试源码上传 `/opt/shinian-validation/releases/t06-20261011`；构建候选镜像，在隔离云测试库验证，不向正式库插入测试内容。
3. 候选通过后，在 root 受控目录备份正式数据库、媒体、源代码、部署配置及运行镜像标识；给当前镜像添加 `shinian-api:t06-before-memoir` 回退标签。
4. 使用已验证候选重建 API，启动时执行兼容迁移；验证健康、迁移版本、既有接口、回忆录只读快照和公网 HTTPS 认证边界，核对正式业务表数量未因验证改变。
5. 上传客户端源码归档、校验清单及本机验证结果以供部署追溯；云服务器不编译 Swift。独立 Release 构建不依赖验证目录，安装到用户指定模拟器。
6. 用户人工审查通过且明确授权后，按云端 → 验证目录 → 主工程提交并推送，记录各自提交号与镜像及源码校验值。

## 回退

### 验收期间的生成按钮修复（2026-10-11）

修复地点补充误判及生成措辞与动作不一致，不新增迁移，不改前端或回忆录排版。分析模型新增有原文依据的兼容地点判断，后端保留真正冲突和证据校验。先在隔离库验证，再以合成讲述验证真实模型。发布目录为 `/opt/shinian-validation/releases/generation-place-fix-20261011`；部署前另备份现有数据库、媒体与 T06 未提交源码，回退标签为 `shinian-api:rollback-generation-place-fix`。正式验证只读；对已受影响的当前对话修复须核对最新消息身份和版本，不添加新讲述、不保存回忆、不覆盖后续用户输入。人工审查前仍不提交。

- 应用异常时先保留当前数据库和媒体，使用备份的旧镜像及配置恢复 API。旧版本不读取新增表／字段，保留 T06 数据可避免丢失已同步制作设置。
- 不在已有回忆录设置或独立封面照片时自动执行数据库降级。迁移本身拒绝这种降级，须先另行备份并明确处理新增数据。
- 若确需恢复数据库备份，先停止写入并备份故障时数据库与媒体，再配套恢复原数据库、媒体和源码；会丢失备份后新增业务数据，因此不能将此操作作为普通重试。
- 不清理回退镜像、备份或用户照片来代替修复。失败记录保留在独立验证目录和云端受控验证目录。
