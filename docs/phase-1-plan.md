# 拾年第一阶段实现方案

状态：需求与技术栈已逐项确认。2026-10-10 第 1–3 次提交获开发、验证和推送授权；后续任务仍为计划。本文不代表所有功能已完成或已部署。

## 交付目标

子女协助父母讲述真实故事，通过语音转文字或文字输入与 AI 对话，附上多张照片。故事可以暂停后继续，AI 按信息维度引导并判断就绪，生成父母第一人称的回忆草稿，用户校对后保存。回忆保存后可以修改或整体删除。至少一段已保存回忆即可按人物整理全部故事，调整顺序和照片，预览并导出 PDF。

需求依据为 [需求访谈记录](phase-1-requirements.md)。

## 技术与部署

| 部分 | 已确认方案 | 职责 |
| --- | --- | --- |
| iOS | SwiftUI | 页面、导航、编辑、照片选择、进度恢复 |
| 语音 | 苹果原生 Speech API | 普通话转文字，由子女确认后发送；不保留录音 |
| 云端 | Python / FastAPI | 对话、草稿、回忆、附件与状态管理 |

| 部署 | Docker Compose / Nginx / HTTPS | 沿用已有云端部署方式 |

第一阶段一个家庭共用家庭账号。默认以联网使用为主，未发送或失败的文字和照片在当前设备保存，跨设备恢复以服务器成功保存的内容为准。

正式后端全部运行在云服务器。每个开发任务先完成本机单元验证，再同步云端并通过迁移、运行和对应接口检查，之后才进行 Git 提交与推送。测试源码及日志使用独立验证目录，云端单元测试也使用独立测试库，不在家庭业务库执行测试清理。

语音使用苹果原生 Speech API，配置为 `zh-CN`，以中文普通话作为第一阶段支持和真机验收范围。方言可由子女转述或文字补充；方言识别列为后续能力。识别能否使用需实际检查权限与识别器可用性，不假设一定能离线使用。

## 功能与状态

### 新回忆

选择记录对象；提供自由讲述与可选话题。话题不是强制章节。每次录音手动开始、停止，识别文字可修改后发送。每条消息可包含文字、最多 9 张照片，或两者都有；两者都没有时不能发送。

照片上传前压缩，单张不超过 8 MB，相册原图保持原样。附件与消息、故事关联。纯图片消息保存成功后展示固定提示，不调用 AI，不通过图片补齐故事信息。

### 引导与就绪

引导与就绪作为后端两个职责明确的模块，复用现有模型接入，不需要分别部署模型。

- 引导模块读取已有对话及信息状态，优先追问关键缺口，尽量每次只问一个问题。
- 就绪模块根据经过校验的信息状态计算是否可以建议生成，不依赖固定对话轮数，也不直接信任模型给出的一个布尔值。
- 所需信息包括记录对象及主要人物、具体事件与基本经过、时间、地点、感受。细节用于丰富故事。
- 时间、地点和感受必须有具体、模糊或明确未知的表达。尚未采集不等于记不清。
- 用户主动点击生成时也需检查缺项；不能默默把缺项填成未知。明确拒绝讲述的内容按用户意愿保留“暂不提供”的状态，不改写为“记不清”。
- 发现关键矛盾时提问确认，不自行挑选答案。允许修改此前信息，并更新就绪状态。
- 图片数据不进入模型输入；不能声称看过照片。纯图片消息的固定提示不作为讲述事实提取。

建议采用的信息状态：

| 状态 | 含义 | 表达示例 |
| --- | --- | --- |
| missing | 尚未提供 | 应继续询问，不能自动标记未知 |
| known | 已明确说明 | “1982 年，在苏州” |
| approximate | 模糊但有信息 | “大概刚参加工作时，在老家附近” |
| unknown | 用户明确记不清 | “具体时间已记不清” |
| withheld | 用户明确不想提供 | “这部分暂不愿讲述” |

每项保存状态、可读文字和原始消息依据。精确日期仅在有依据时用于计算；未知或模糊时间仍有可读表达，不用虚构日期代替，也不向用户只返回 null。

### 暂停、恢复与失败

成功发送的消息保存在服务器。App 提供未完成故事入口，重新进入可加载已有消息及附件继续讲述。当前设备的未发送文字与已选照片持久保存，重启后恢复。

建议为消息、上传和草稿确认使用稳定请求标识。超时重试返回同一结果，避免重复消息、照片与已保存回忆。多张图片部分上传失败时保留上传状态；未完成保存前不展示“照片已保存”。AI 失败时保留已发送内容并提供重试，不伪造回复。

### 草稿与已保存回忆

草稿默认采用记录对象第一人称。可以直接编辑标题与正文，或返回对话补充后重新生成。重新生成不能静默覆盖手动编辑，确认保存必须提交用户当前修改的内容。

已保存回忆可以修改标题、正文、时间、地点、感受和照片。不同设备同时编辑时建议使用版本校验：发现旧版本保存则提示重新加载，并保留本机修改供核对，不静默覆盖其他设备内容。

删除前明确说明会删除故事及对应对话、草稿和照片。建议先在数据库事务中删除关联内容，再按可重试方式清理物理图片，避免一部分删掉、一部分残留。App 外已导出 PDF 不受影响。

### 回忆录与 PDF

按记录对象收录全部已保存故事。不能因为妈妈仅出现在爸爸的故事里，就把爸爸第一人称的故事放进妈妈的回忆录。

默认按有依据的发生时间排序；保留模糊时间描述，不能确定先后的放在最后，允许手动调整。日期不明确时不使用创建日期冒充故事发生时间。

默认选中每篇故事的全部照片，允许取消选择与调整顺序；照片放在所属正文之后。整本保留已确认的正文，不再次调用 AI 重写。封面和目录自动生成，名称可修改。

建议首版使用简洁中文排版、页码和 A4 页面尺寸。根据最终排版生成目录页码，并处理长故事、长标题、竖横照片与分页。图片加载失败时提示重试或由用户取消收录，不能静默漏图。

导出前建立本次内容快照，再预览、生成与分享 PDF。后来修改故事只影响新导出的文件，已经生成的文件保持原有内容。

## 数据与接口调整建议

### 工程与验证文件分离

按用户要求，测试源码、验证脚本及开发中间产物使用主工程之外的同级目录 `/Users/student03/Desktop/shinian-validation/`。主工程 `/Users/student03/Desktop/shinian/` 保留产品源码、部署文件、正式需求与交付文档。

验证目录按 `tests/ios/`、`tests/backend/`、`scripts/` 和 `artifacts/` 分类。日志、截图、测试结果、临时 PDF、构建缓存与测试数据库等放在 `artifacts/`，不提交 Git；测试源码和验证脚本应独立保存版本，并记录所验证的主工程提交号。它们不会随主工程仓库自动上传。

现有 Xcode 测试目录、后端测试目录与验证脚本尚未迁移。迁移时必须同步调整 Xcode 测试配置、pytest 路径与验证入口，避免留下依赖本机绝对路径的项目配置。老师仅获取主工程时，应仍可按 README 构建运行 App；执行开发测试才需要验证目录。App 运行时的待发送内容、云端照片和数据库属于产品数据，不归入开发中间产物。

| 内容 | 现有基础与不足 | 建议调整 |
| --- | --- | --- |
| 讲述信息 | 时间为可空日期，地点可空，感受未独立建模 | 增加各维度状态、可读描述、原文依据；保留精确日期作为有依据时的辅助值 |
| 多图消息 | 媒体主要关联会话和回忆，前端按单图处理 | 增加消息关联和顺序，支持文字可空但附件存在的消息 |
| 对话恢复 | 已有持久消息与会话 | 增加未完成会话列表、状态获取与恢复入口 |
| 草稿编辑 | 已有草稿及 revision | 支持保存用户编辑后的草稿，确认保存该版本 |
| 回忆维护 | 当前路由具备列表、创建和获取 | 补齐版本化更新、整体删除、附件维护 |
| 回忆录 | 尚未完成导出 | 按记录对象获取全部已保存故事，本地排序、排版、预览与分享 |

新字段通过 Alembic 兼容迁移。旧记录不得被标记为已采集完成；无法从现有内容可靠恢复的状态作为待补充，不触发额外付费 AI 调用批量补齐。
