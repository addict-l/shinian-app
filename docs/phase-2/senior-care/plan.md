# 老人关怀模式

用户于 2026-10-16 确认：保留普通版，在 App 内切换关怀模式并记住选择；优先老人独立讲述与回看。用户于 2026-10-17 确认将紧凑版交互设计接入真实 App。

## 已确认的界面与交互

- 默认正文 22pt、主要按钮至少 64pt 高，支持系统动态字号。
- 首页、回忆、更多三个主入口；普通模式沿用四个标签。
- 居中的短标题和自然换行；核对信息分组，六个话题常规字号下两列排列，辅助功能字号改为单列。
- 人生问答和讲述历史一次查看一组，提供上一条、下一条和明确返回。
- 语音点击开始、点击结束，转成文字后核对、发送；保留打字、照片、跳过、暂停及幂等重试。
- 真实人生概览核对、六模块选择、聊天、草稿编辑及保存共用现有 API 与数据状态；只有服务器保存成功才显示完成页。
- 已保存内容可直接打开阅读，也可回首页或继续讲述。回忆正文使用可缩放的 SwiftUI 文本。

## 业务提交

模式切换与完整关怀流程合成一个可独立验收的提交：`新增可切换的老人关怀模式`。范围为主线 `front-betterui` 的模式偏好、导航、关怀展示组件、现有讲述／草稿视图的展示分支、Debug 验证适配器及对应 UI 验证。后端使用现有已发布镜像，接口契约不变。

开发前基线为 `main` 的 `5c96992` 和用户当时的工作区。仓库外 `../shinian-validation/artifacts/senior-care-20261016/baseline` 保存开发前 Swift 源码与已有 diff；正式提交只包含本次增量。

## 验收

1. 普通版开启关怀模式，重启仍记住选择；取消切换保留当前模式，确认后恢复普通版。
2. 指定现有 iPhone 17 Pro（iOS 26.0，`8801F7F7-7154-4AEB-88F2-1E77A8393190`）构建、安装和实际操作。
3. 正常字号下核对／六模块接近一屏；最大系统字号、横屏不遮住关键操作，历史可以逐条阅读。
4. 草稿修改后保存，完成页及阅读页显示服务器返回的已保存内容。
5. 阿里云独立候选、独立测试家庭联调真实人生概览、工作模块、讲述、生成、保存和重新启动回看。
6. 语音权限拒绝后有说明并能改用打字；加载／失败保留既有输入及待重试请求。
