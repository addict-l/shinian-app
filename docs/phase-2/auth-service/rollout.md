# 正式账号服务切换

## 发布前准备

1. 只打包本块审核通过的提交，不能把工作区里尚未审核的访谈、UI 和文档整理一起发布。正式配置、证书、认证文件及数据卷保持原位置，Compose project name 保持 `backend`。
2. 原家庭 ID 固定为 `60d34ec1-aa9d-5d17-8e5e-cdf5831747ba`。从设备已有凭据或维护者受保护的输入获取原账号密码，只用于绑定此家庭；不写进命令参数、日志、Git 或截图。如果无法取得原密码，停止切换，不创建替代家庭。旧账号名与默认 `family` 不同时，配置 `LEGACY_FAMILY_USERNAME` 为原账号规范化名称。
3. 确认所有使用者能更新客户端。新后端不再接收旧 Basic 登录，旧版本必须升级；不得为兼容旧版保留可绕过家庭校验的业务入口。
4. 按 [生产部署文档](../../../cloud-deployment/backend/DEPLOY_ALIYUN.md) 备份步骤，安排停写窗口，保存 SQL、媒体、旧 API 镜像、源码、环境文件、Nginx、Basic 认证及 TLS 配置到权限 0700 的服务器目录。停止 API 后再从媒体卷取快照，避免停写期间后台照片清理改变文件。确认备份可读取。
5. 在旧运行容器仍可读时，用 `scripts/family-data-manifest.py` 记录全部业务表和媒体的计数、摘要，再停 API；或在 API 停止后用旧镜像及同样只读连接挂载执行。脚本可单独复制到旧容器，不依赖新模型。不要把旧迁移状态误当成业务数据摘要。

## 切换顺序

维护窗口保持公网维护提示，直到全部检查完成。先保留原 Nginx Basic 配置；不要先卸掉入口认证。

1. 构建已审核镜像，连接原数据库和媒体卷，执行 `alembic upgrade head`，检查版本为 `h10100000001`。只有新增账号表，不搬动、重建或清空旧家庭。
2. 使用受保护 stdin 向容器内 `python scripts/bind-existing-family.py` 传入 JSON，字段为 `username`、`password`、`family_id`。绑定命令拒绝不存在家庭及冲突绑定，重复相同输入可安全重试；仅输出非敏感状态。凭据对象不得被 shell 回显或输出。
3. 在停写状态再次执行数据摘要，必须与迁移前逐表、逐媒体摘要完全一致；核对原家庭、3 位家人和 12 条回忆的 ID。计数为 2026-10-16 发布准备时只读记录，正式执行以停写时基线为准。
4. 启动新 API，先经服务器 loopback 验证健康、原账号登录、原家庭只读列表，以及无令牌业务请求为 401。临时测试登录结束后撤销该测试会话，不能在生产库运行测试清理。
5. 将现有 HTTPS 站点配置备份后，按 `cloud-deployment/nginx/aimemory-session.conf.example` 安装会话版配置，沿用现有证书和域名。业务授权交给新 API，移除 Basic gate，透传 Bearer，并覆盖外部传入的 X-Forwarded-For。先 `nginx -t`，通过后 reload。不要让旧、新站点同时重复声明相同域名。
6. HTTPS 检查未登录业务 401、原账号登录成功、原家人与回忆保留、图片可读。使用更新后的 iPhone 17 Pro App 验证会话恢复及当前设备退出。注册、跨家庭、双设备完整场景在隔离候选已验证；生产只做必要只读检查。记录正式提交、镜像、迁移、摘要与发布时间后结束维护。

## 回退

不能在新家庭已经注册后直接切回未隔离家庭的旧 API。旧 API 的全量列表可能暴露其他家庭，旧固定家庭 bootstrap 也不符合新模型。

出现问题先切维护入口并停写，保留当前 SQL 与媒体，再决定修复新服务或回退。若确认尚无新家庭写入，可恢复旧镜像与原 Basic Nginx，保留新增认证表，不执行 downgrade。若已有新账号／家庭，必须继续维护模式并修复，或经用户明确批准后进行数据库、媒体成对恢复；恢复会丢弃备份后的写入，不能自动执行。`h10100000001` 的 downgrade 在已有账号时拒绝删除认证表。
