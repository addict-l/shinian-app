# B03：回忆时间修改与标题正文联动

日期：2026-10-13（Asia/Shanghai）

状态：实现与本地、隔离云端、原模拟器验收完成，第 26 问用户已通过人工验收并授权提交推送 main。沿用已确认的需求与设计，第 25 问已确认保留手改时间。

## 已确认的业务范围

- 草稿和已保存回忆都支持编辑时间，区分确定、大概记得、记不清、暂时不想说和待补充。
- 修改时间后提供标题、正文的对应建议，显示修改前后文字；只应用用户选中的建议。
- 有多个事件、多个日期或归属不明确时，保留原文并单独提示用户选择，不能全局替换所有年份。
- 用户手工改过的文字、取消后的输入、失败后的编辑内容和多设备版本保护继续保留。
- 保存后读取核对时间状态、精确日期与排序；新增时间更正不伪装为聊天原文证据。
- 拟用提交标题：`支持回忆时间修改与标题正文联动（B03）`；完成本地、隔离云端及原模拟器验收后提供人工检查材料。

## 开发开始时的调查（对应功能现已实现）

- 后端时间存放在草稿 `payload.information.time` 和回忆 `information.time` 中，精确日期另存 `memory_date`。
- `DraftUpdate` 只有 revision/title/summary；现有草稿编辑没有时间字段。
- `MemoryUpdate` 已含版本和时间信息，保存时只更新 metadata，不提供标题/正文建议。
- 草稿重新生成重新读取 session 信息和聊天依据，并替换完整 payload；仅把手改时间写入旧 payload 会被重新生成覆盖。
- 客户端 `JournalDraftEditorView` 只有标题/正文；`JournalMemoryEditorView` 已有时间编辑和版本冲突处理。
- 当前业务基线为已推送主分支 `9ebb0a6`。本次功能已实现，验证结果见 [B03 验收记录](phase-2-b03-verification.md)。

## 已确认：第 25 问

用户确认：保留用户确认的手改时间；重新生成的新草稿继续预览标题和正文校对。原聊天保持原样，手改时间标记为用户更正。


## 验收场景

1. 精确日期、只有年份、季节及大概时间；标题没有时间时不强行添加。
2. 正文多个事件或日期、跨年及相对时间；不误改其他经历。
3. 记不清、暂时不想说、待补充；不自行推断日期。
4. 先手改正文再改时间、连续两次修改时间、取消建议、只选部分建议。
5. 建议生成失败和重试；保留用户输入，不偷偷保存。
6. 草稿手改时间后的重新生成、确认保存与再次读取。
7. 其他设备更新、旧预览过期、重复请求；保护版本及幂等行为。
8. 隔离云端联调与现有 iPhone 17 Pro：检查文字建议、保存时间、排序与失败恢复。
