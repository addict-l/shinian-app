# 六模块三层采访接入

日期：2026-10-15。用户已确认：人生回望按表达验收，不强求五个故事；新聊天默认启用，旧聊天明确切换，保留进度和草稿。当前为待审代码与隔离候选，不代表正式域名已发布。

## 本块范围

将后端三层调度和六模块题库作为一个完整业务块验证与审核，拟用提交标题 `feat: integrate six-module three-layer interviews`。现有客户端沿用聊天入口，以模块名称或“聊工作”等明确命令选择模块，不需要新增界面。

- 新人物的预备聊天以及省略 interview_module 的新人物会话默认启用新流程。先选模块，再依固定基线推进。显式 null 兼容旧 API；未指定人物的普通聊天继续使用旧方式。
- 同一旧聊天保存后的内部新片段仍属于旧聊天，不偷偷启用三层。旧会话可通过明确命令或版本受控的切换接口接入，已讲原文由事件层重新读取。已有未确认草稿时先核对保存，切换返回 409，草稿不被覆盖。
- 事件 AI 提取题目合同要求的逐字证据，控制器计算覆盖并选一个必要缺口；回答 AI 只检查当前小目标，额外原话继续交事件层。模块 AI 在实际保存后的交接点检查重复、关键矛盾。每轮只展示一份回复。
- 进度、已问目标、未知/拒绝、暂停、题号、已存故事和模块检查结果均入 JSON 状态，可重进恢复。旧童年 v1 已核实数量兼容迁移，不把未完成记录补成合格。
- 每模块六个基线入口。故事、有效表达素材、处理过的题目分别计数；跳过不生成故事。Q/D/V/K 不强求故事动作；人生回望已有本人有效表达即可提醒整理当前章节。
- 其他模块以约五份不同且有效的已存素材作为整理提醒目标，其中确有故事；包含原话、对照或寄语时如实记录材料类型，不声称这些全是故事。保存和导出不由该提醒门槛锁定。
- 讲述尚未核对保存时切换模块会要求先保存，以保留该段及草稿。空段或模块收尾后可切换，再返回时恢复对应检查点。
