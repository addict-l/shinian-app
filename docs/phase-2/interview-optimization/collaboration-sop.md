# Claude 与 Codex 采访优化交接 SOP

版本 1，2026-10-23。Claude 持续优化采访，Codex 负责整合、部署和独立云端测试。每轮用固定提交和双向交接单接续工作，让云端发现的问题回到下一轮优化中。

本 SOP 规定交接内容，不替代 [project-development](../../../.agents/skills/project-development/SKILL.md) 的开发流程。业务依据仍为[采访业务基准](../../interview-development-baseline.md)，环境入口仍为[项目环境说明](../../../.agents/skills/project-development/references/project-environment.md)。已有用户决定和本轮授权继续沿用；新增业务边界或缺少生产发布授权时，才补充确认。本 SOP 本身不构成无限期自动发布授权。

最新回执从[版本台账](README.md)进入。首份实例：[2026-10-23 云端发布与问题回传](handoffs/2026-10-23-cloud-release.md)。

## 一 分工

| 参与者 | 负责交付 | 决策边界 |
| --- | --- | --- |
| Claude | 题意、判定与说话层优化；本地评测；候选代码、运行包及已知问题 | 依照已确认业务范围优化；题库、顺序、完成标准等业务变更先按业务基准确认 |
| Codex | 代码整合、持久化与接口兼容、候选部署、生产发布、云端独立验证、原始问答和问题回传 | 授权范围内完成工程修正；发现新的采访行为取舍时，给出具体复现和建议，再确认新增范围 |
| 用户 | 业务取舍、质量目标、生产发布授权、是否合并 main | 明确限定本轮或持续授权的范围，双方共同沿用 |

Claude 不直接改生产配置。Codex 不把工程整合顺手扩成题意、阈值或收口策略的重新设计。需要双方修改同一路径时，先在交接单列明谁负责哪一块。

## 二 每轮先对齐代码基线

1. 双方先读取最新回执，核对共享分支、当前生产代码 SHA 和上轮未解决问题。记录完整的 `base_sha → candidate_sha`，使用固定 SHA 接收和测试。
2. 采访优化沿用 `interview/question-optimization` 分支例外：可交付版本推至该分支，用户审阅后再合入 `main`。分别记录优化分支头、整合代码和生产代码，Git push 不等于部署。
3. Claude 从已回传的最新共享基线继续，确认上轮 Codex 修正已经继承。首次接续本 SOP 时，须继承 `770f841` 的骨架题序修正；以后以最新回执列出的整合修正为准。优先保留提交历史；若移植为等价实现，列出对应改动及回归证据。
4. Claude 交接固定候选后，Codex 在独立工作树整合。同一共享分支进入整合窗口时，由 Codex 写入整合提交；Claude 可在另一个工作分支继续实验，待回传后再同步共享基线。保留各自未提交的工作，正常合并远程变化。

完成条件：双方能指向同一候选 SHA；上轮修正有继承记录；没有把脏主工作区或未测实验混入发布版本。远程更新造成冲突时，整合后重测受影响行为，再确定新的接收 SHA。

## 三 Claude 交给 Codex

每个候选提交一份 `handoffs/<日期>-<候选短 SHA>.md`，并在台账增加入口。提交前用下面的模板自查，未执行项直接写明。

```text
方向：Claude → Codex
目标：本轮解决什么；给出一个原行为 → 预期行为的例子
代码：branch / 完整 base_sha / 完整 candidate_sha
继承：上轮 Codex 修正 SHA；未继承项及原因
范围：改动路径；题库、接口、存储、旧会话及模型配置是否受影响
运行包：版本、manifest SHA-256、构建与 --check 命令
本地验证：实际命令、数据版本/哈希、缓存或真实调用、通过/计划分母
模型：判定/复核/说话/模拟受访者/评分器各自的模型与参数
已知问题：未通过、跳过、未执行及未覆盖场景；保留失败样本
证据包：附件名、SHA-256、获取入口、所需目录与复现命令
交付状态：待整合；本轮用户已确认的范围和发布授权引用
```

运行包与评测实现一起交接：提示、配置、引擎、桥接、必要测试和生成脚本应来自同一候选。说明默认开关和启用条件，尤其是已有题目的 pipeline 标记、pending 请求及缓存调用如何继续。当前固定题库为 83 题，模型调用继续关闭 thinking，参数中省略 `reasoning_effort`；修改这些约定须先走业务确认。

证据按实际来源标识：缓存回放、固定模型夹具、真实模型直调、候选 MySQL HTTP、生产 HTTPS。各类结果分别列分母、失败、错误、跳过和未执行数量。单次开发集关键点成绩不替代完整流程、留出集或既有的正式连续三轮质量门槛。

可共享的脚本、最小脱敏回归和文件指纹进入仓库。测试原文、gold、缓存和调用记录按现有资料规则另交数据包；秘密配置留在受控环境，仅写配置引用。跨机器交接必须有接收方可取得的附件或入口，只有 `/Users/...` 路径不算资料已交付。资料不可得时，标记对应项目“无法复现”，并继续不依赖它的整合工作。

完成条件：Codex 能检出候选、校验运行包，按说明运行最小回归；不足的资料和验证项目已经明确列为缺口，不能把旧成绩换名为本轮新验证。

## 四 Codex 整合 部署与云端测试

按项目开发与[部署说明](../../../cloud-deployment/backend/DEPLOY_ALIYUN.md)执行。交接中重点核对以下结果，不再另建一套审批循环。

| 阶段 | 必须留下的结果 |
| --- | --- |
| 接收与整合 | 固定候选、远程变化与上轮修正核对；改动文件和状态兼容审查；Codex 修正单独提交，说明原因及回归 |
| 本地验证 | 运行包 pin、题库一致性和相关回归；真实执行数量与跳过原因；保留失败记录 |
| 云端候选 | 独立数据库和媒体目录；真实 MySQL 持久化往返、真实 API 和模型；正式业务数据不参与写入测试 |
| 生产发布 | 授权引用、备份与可读性校验、镜像 digest/代码 SHA/pin、切换记录、健康及权限检查、业务数据指纹、可用回退方案 |
| 生产问答 | 正式 HTTPS、独立测试家庭、两层同时启用；逐轮 API 原文、状态、provider response ID、模型参数与请求摘要 |
| 客户端验证 | 按实际范围记录构建、只读解码或产品 GUI 操作；各自明确覆盖到哪一步 |

云端回归至少覆盖：完整骨架题序及说话层下一题一致、缺项追问、明确未知、本人拒答、历史/他人/否定语境、暂停继续、重复请求、失败后重试、旧题与新题流程切换，以及模块的补充、核对和草稿衔接。按本轮改动补充边界，不以 `/health` 成功代替业务验证。

问答采样中，AI 受访者只读取原始材料和可见对话，不读取 gold、目标字段、内部判定或评分结果。保留调用失败、回退话术、重复提示和无补充后的行为。设置有限采样上限；截断时同时写 `sample_cutoff`、后台真实 phase 和 `natural_completion`。HTML/TXT/原始记录应逐字对应，模型响应 ID 和参数另做一致性核验。模拟受访者、真人、缓存与真实调用的身份在导出中明确标注。

失败时先核对已执行阶段，按对应阶段恢复。已有发布目录保留原证据，续跑缺失步骤；停服后的恢复与已替换容器后的兼容回退分开处理。已开始 v3 的题需要保留能识别 v3 状态的镜像及 runtime 配置，按本轮回执确定回退方式。

完成条件：交接单写清候选是否通过、生产是否已切换、质量目标是否达成，三者分别给证据。未获本轮生产授权时，候选与审核材料可以完成，生产状态保持“未发布”。用户明确限定先只部署并观察时，记录其接受的未解决问题，不改写为质量验收通过。

## 五 Codex 回传给 Claude

Codex 在共享分支追加回传单，把产品提交与部署/验证工具修正都交清，并更新台账当前状态。原始失败记录保留，复测另有结果。

```text
方向：Codex → Claude
版本：接收 candidate_sha / 整合代码 SHA / 生产代码 SHA / 共享分支
状态：候选验证 / 已部署或未部署 / 质量结论；各自写证据
Codex 修改：每个提交的路径、原因、行为变化、回归、下一轮继承要求
部署工具修改：脚本版本/哈希、触发条件、原错误、恢复和最终修正
云端配置：镜像 digest、pipeline、runtime pin、兼容与回退条件（仅非秘密元数据）
测试结果：各层实际执行数量、分母、失败/跳过/未执行；说明数据和调用方式
问题：原始输入 → 实际回复/状态 → 预期行为；复现方式和证据出处
问答：HTML/TXT/原始审计附件；受访者身份；截断和未完成状态
待办：Claude 下一轮负责的问题、Codex 留下的工程事项、仍需用户决定的事项
附件：双方可取得的包名、SHA-256、依赖和访问缺口
下一轮基线：从最新共享分支继续，并继承列出的整合修正
```

问题注明“哪个环境、哪种调用已经复现”：例如夹具复现不能写成云端模型复现；审计原文一致不能写成采访质量满分。Claude 的自评与 Codex 的独立检查分别署明方法，不把同一次缓存结果当作两次独立验证。

秘密、真实家庭原始数据和数据库备份不进 Git 或交接附件。附件按白名单打包，扫描凭据字段及实际秘密值，登记 SHA-256；部署辅助脚本也必须有可读取的源码或补丁，不能只剩本机路径。

默认交接通道是共享仓库与交给用户的附件。需要直接给另一个聊天、账号或第三方发消息时，沿用用户对该接收方和用途的明确授权；不因 SOP 自动转发材料。

## 六 下一轮如何接续

Claude 读取回传单后，在下一份候选单列出“已继承修正”和“逐项处理结果”。每个问题注明已修复及证据、仍存在或本轮不处理及原因。Codex 接收下一候选时检查这张表，重复出现的问题继续保留同一问题编号。

一轮协作完成的标志是：固定代码可检出、双方修正已回到共享基线、证据可取得或访问缺口已列清、线上状态明确、下一轮责任明确。部署成功后仍可有采访质量待办，继续进入下一轮，不把失败样本移出统计来获得通过结论。
