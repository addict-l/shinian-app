## 目标

故事题深挖：23 道故事题在本题要素齐之后、收尾之前，最多再请老人多讲 2 次细节（敏感题 1 次），为写回忆录攒素材；同时把“记不清但接着讲”只当作那一点记不清，并让承接与转题温暖、不复述。以新的 pipeline 值 `v3j_v5f` 启用，默认不变。例子（原行为 → 预期行为，来自模拟访谈，受访者为模拟老人）：

- 深挖：老人答“最感谢张隽先生，那时我情绪最差，他叫我去弹琴。”（引擎 ready）。原来（v3j_v4d）：一句承接 + 草稿句。现在：先问“张隽先生是怎么叫您去弹琴的？”，老人讲出“军中电话很难打……民本电台有个现场节目……正好是礼拜天”，这段原话记入本题来源（不判定、不改字段），然后才是承接 + 草稿句。
- 部分记不清：老人答“这个我记不太清了。就记得厂里的老师傅给我们做媒，还请我们吃了一顿饺子。”原来按“记不清”收尾、说“记不清就不勉强”；现在只不追记不清的那一点，深挖顺着“老师傅做媒”问下文（仍在 2 次上限内）。
- 温暖转题：原来 v4d 几乎每次“复述老人上一句 + 那咱们再聊聊 + 下一题”；v5f 一句温和、具体的话（“那会儿家里难，”“来得真是时候。”“难为您了。”）+ 自然过渡，同一会话里同一转题短语第二次出现由代码删掉，复述承接由代码删掉。

本轮遵守的用户决定（2026-10-26）：故事题清单（23 道）、敏感题只深挖 1 次、短答门槛、最多 2 次全部按《故事题清单》默认执行（用户已确认）；“那咱们再聊聊”这类转题话可以存在，但要温暖自然、不每次复述/总结上一句；采访“做得差不多就行”，小问题云端实测再处理；一切以写好回忆录为导向。

## 深挖在后端的做法（与模拟器的差异）

| 情形 | 模拟器 v5f | 后端 v3j_v5f |
| --- | --- | --- |
| 何时考虑深挖 | 故事题，收尾规则给 `done`（或 `unknown_partial`）时 | 相同；访谈入口在草稿步骤前，骨架 SK01c 在转下一道骨架题前；补充阶段（草稿提示之后）不深挖 |
| 门槛、输入、校验 | `deepen_gate` / `deepen_user` / `check_deepen` | 相同函数（回放逐字相同） |
| 深挖回答 | 不判定，记入本题 `deepen_sources` | 不判定，记入 `contract_state.deepen.sources`；不进 `sources`，所以之后补充阶段的判定也不会读它；草稿生成照常读会话全部消息，深挖回答在其中 |
| 深挖后收尾 | `deepen_close` 后直接问下一题 | 访谈入口：说话层输入同模拟器，只取承接 + 原草稿句（同 v4d 的草稿步骤）；骨架：收尾 + 下一道骨架题，与模拟器相同 |
| 调用失败 / 模型不问 / 校验不过 | 不深挖，按原收尾 | 相同（草稿步骤或转下一道骨架题），不发固定问句 |
| 深挖等待中老人说“跳过” | 按已答收尾（`declined_partial`） | 访谈入口：草稿步骤（收尾原因“老人不想多说”），不记为跳过；骨架：按已答收尾，状态 `known` |
| 深挖等待中老人说累了 | 先歇，点“继续”后进下一题 | 保持现有暂停；本题不再深挖（`deepen.stopped = rest`），“继续”后回到本题入口问题（与 v4d 累了后的做法一致） |
| “暂停”控制词 | — | 现有暂停，待处理的深挖问句保留，“继续”后重问它，回答仍按深挖回答处理 |
| 转题短语重复（`template_guard: repeat`） | 同一模拟会话的更早收尾 | 本次采访更早各题审计里的收尾文字（访谈入口取本模块 `contract_history`，骨架取各骨架题审计）；无新字段 |
| “上次换话题时你说的” | 上一题整句 | 同 v4d：草稿步骤后只记显示过的承接 |

- **贴合未达参考**：守卫删掉复述承接后不补别的话，个别收尾变成光秃转题（模拟里李福英 CH05“那咱们再聊聊，……”贴合 2）；心疼的话有时太泛（“没事”“难为您了”）。在访谈入口这类收尾只影响草稿句前的承接（光秃时只发原草稿句）。
- **深挖守卫偏严**：`no_repeat_last` 误拦过一次新细节（“那天在电台弹琴，弹的是什么曲子？”）；`no_yes_no` 拦下的“后来她们也录取了吗？”在上一轮恰好引出了好素材。两者使深挖次数和素材低于 v5e。云端如果发现深挖太少，可先关 `no_repeat_last`（需重建运行包并换 pin，属于说话层调参，按 SOP 回到 Claude）。
- **说法覆盖**：“这个还真不好说 / 没有特别哪一个”不在信号与 `DEEPEN_UNKNOWN` 里，模拟里因此多问了一次（repeat_ask + should_have_stopped）；“不好说”这类说法建议在 C 系列规则里统一补。
- **预设仍偶有**：深挖“爸妈反对，后来是怎么同意您去的？”（预设结果），提示里有规则但模型没守；v5e1 留出组的“您也累了”、收尾“是……”下结论（“是实在话”“是挺暖的”）只靠提示，没有代码检查。
- **v5e1 报告剩余项的处理**：人名 / 专名放宽、删到只剩语气词、第二问重复、“吗”结尾——本轮已有代码守卫；“是……”下结论、替老人说累了——未加代码检查。
- **模拟器字数天花板**：模拟老人“正常回答”按设定每次 30–100 字、短答 8–25 字，每题资料约 1000 字（`persona.MATERIAL_CAP`），深挖问到资料外只能说记不清（本轮 10 次深挖中 4 次）。故事题字数在模拟里到不了 150 字/题，真人能讲多少需要云端或真人验证。
- **未经真实验证的后端路径**：深挖在访谈入口与骨架的完整往返、深挖后草稿步骤的承接、`template_guard: repeat` 跨题（模块内）读历史、累了 / 跳过 / 暂停发生在深挖等待中，都只有固定夹具与模拟回放，没有真实模型回复。

## 建议的云端实测场景

在候选 MySQL + HTTPS、独立测试家庭、`INTERVIEW_PIPELINE=v3j_v5f` 下：

1. **故事题深挖**：工作模块 WK01、家庭模块 FM01 / FM04b、回顾模块 RV06 / RV13 各一题，老人第一次就讲清楚（引擎 ready），确认深挖 1–2 次、问句接老人一笔带过的人或事、深挖回答进入草稿、之后草稿步骤与补充 / 核对 / 保存照常；审计里有 `deepen_answer` 记录、`contract_state.deepen.sources`。
2. **部分记不清**：深挖或追问时回答“那天的事记不清了，就记得后来……”，确认不收尾、深挖输入带“老人刚说记不清的 / 他接着讲的”、只问一次新内容；整句“记不清了”仍体谅一句收尾。
3. **温暖转题**：连续 4–5 题的拒答转题与骨架转题，确认“那咱们再聊聊”这类话同一采访里不重复、没有复述老人上一句、没有只剩“噢，”的残句；讲到苦处时的心疼话是否自然。
4. **敏感题**：WK09、FM03、RV02 只深挖 1 次、问法轻（“要是愿意的话……”）；老人不愿细说时直接收。
5. **短答**：首答 ≤12 字不深挖；深挖后回答 ≤20 字不再问。
6. **骨架 SK01c**：深挖后接下一道骨架题，状态 `known`，概览字段不因深挖回答改变。
7. **控制与重试**：深挖等待中“跳过”（应给草稿入口）、“累了”（暂停，继续后回到入口问题）、“暂停 / 继续”；深挖调用超时或失败后重试不重复调用；v3j_v4d 进行中的题切到 v5f 后不被接管。
