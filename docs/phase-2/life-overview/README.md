# 人生骨架与人生概览

本业务块接通“七题人生骨架 → 本人核对／更正 → 选择六模块 → 三层访谈”。沿用用户提供的两张页面布局。保留家乡与童年、求学与成长、工作与劳动、家庭生活、后来的生活、人生回望；不新增人生转折模块。骨架中的生活变化仅作为已披露背景。

## 已确认规则

- 七题为成长地点、读书或学艺、年轻时的生活重心、后来的变化、重要家人、记得的生活变化、如今的生活。一次问一题，不在骨架阶段追问故事细节。
- 一次回答明确覆盖多个话题则复用。简短回答可推进；未提供、记不清、不愿讲和跳过分别记录。不推断姓名之外的经历、婚姻、职业、退休或精确年月。
- 新人物创建成功后直接进入人生骨架页面；不经过人物选择或独立聊天开场白页面。创建时准备固定第一题，不调用模型生成问候；网络等待只显示打开记录状态。旧人物缺少骨架时只提供主动补录入口。已有采访、草稿、输入和照片保留。
- 全部问题已答或明确跳过后展示概览。本人确认才标记“已核对”；更正后重新核对，原始讲述保留。
- 选择模块后接入已上线三层访谈。骨架作为有引用的背景，不能混入当前故事原文或补足当前故事的操作经过。

## 实现与交付

一个完整业务提交块，拟提交标题：`接入人生骨架与概览核对选择流程`。

- 人物级 `life_interview` JSON 与增量迁移 `g10100000001`，独立于可删除的故事会话。旧人物保留 NULL；没有 GET 时自动填充或修改旧人物。
- `GET /api/v1/chat/sessions/{id}/life-overview` 只读；`POST .../life-overview/actions` 执行开始、回答、跳过、核对、更正、暂停和恢复。使用独立概览版本与可重放请求标识。模型失败前原话已持久化；重试不会创建重复回答。
- iOS 复用真实会话、文本及语音输入。新流程自动出现，旧聊天通过“人生概览”主动进入；大字号时板块卡改为单列。录入草稿和未完成请求按人物保留。
- 构建、阿里云隔离候选、iPhone 17 实际联调完成后提供审核材料。人工审核通过再 commit / push；正式发布另需明确授权。

验证结果见 [verification.md](verification.md)。用户随后明确要求上传真实后端供实测，已执行备份、发布与只读核对；用户已明确审核通过，并批准将前置功能和取消开场白修正拆成两笔提交后推送 main。
